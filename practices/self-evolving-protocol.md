# 实践: Self-Evolving Protocol — 协议自进化机制

> 提炼自 VoiceOS 3.0 自进化引擎

## 问题

AI 多角色协作协议不可能一次写对。实际执行中必然遇到未预料的情况（角色越界、Spec 格式不够、并行冲突等），如果只是"下次注意"，同类问题会反复出现。需要一种结构化的方式从错误中学习并固化到协议中。

## 方案

当协作出现问题时，不直接"加一条规则"，而是走完整的进化流程：

### 进化流程

```
1. 记录问题: 发生了什么？哪个 Batch？哪个角色？
2. 根因分析: 为什么会发生？是协议漏洞还是执行偏差？
3. 固化规则: 提炼出一条可执行的规则（不是"注意"，而是"做 X"）
4. 更新文档: 修改 AGENTS.md / 角色定义 / Spec 模板
5. 标记版本: 协议版本号 +1（如 v4 → v5）
```

### 进化日志格式

```markdown
# 进化日志

## E-001: 并行文件冲突
- **日期**: 2026-05-20
- **触发**: B88 两个 Agent 同时改 Dashboard.tsx
- **根因**: Spec 没有声明文件修改范围
- **固化规则**: Spec 头部增加 Locks 字段，声明修改文件列表
- **协议版本**: v4 → v5

## E-002: 角色越界写代码
- **日期**: 2026-05-19
- **触发**: B86 神笔写了 JS 逻辑
- **根因**: 任务天然跨域但没有拆分
- **固化规则**: 跨域任务拆分为多 Part，每个 Part 分配给对应角色
- **协议版本**: v4 → v5
```

### 版本标记规则

- 小改动（措辞优化）→ 不升级
- 新增规则/字段 → minor 升级（v4 → v5）
- 架构级变更（新增角色/流程重组）→ major 升级

## 为什么有效

- **问题可追溯**: 每条规则都有"为什么存在"的记录，未来可以评估是否还需要
- **避免重复犯错**: 同类问题只出现一次就被固化，不会反复踩坑
- **协议持续进化**: 不是一次性设计，而是在实战中迭代优化
- **版本管理**: 可以回溯到任意版本的协议，知道每个版本解决了什么问题

## 适用条件

- 长期项目（> 1 周），协议需要持续优化
- 有审核环节（审核是发现问题的主入口）
- 有版本控制（协议变更可追踪）
- 有指挥者角色（负责判断哪些问题值得固化规则）

## 实战证据

VoiceOS 3.0 在 109 个 Batch 的协作过程中，记录了 **11 条进化日志**，协议从 v1 演进到 v5。关键指标变化：早期 pass rate（一次通过率）约 33%，进化到 v5 后达到 **100%**。每条进化日志都对应一个真实发生的问题和一条固化规则，没有"悬空"的规则。
