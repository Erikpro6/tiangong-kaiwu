# 实践: 增量 Commit — 分段提交减少风险

> 提炼自 VoiceOS 3.0 天工 Git 策略优化

## 问题

所有任务完成后才一次性 commit，如果中途崩溃，所有改动全部丢失。也无法分步审核。

## 方案

按逻辑分组提交，而不是全做完再提交：

| 任务数 | 提交策略 |
|--------|----------|
| 1-3 个 Part | 全部完成后一次 commit |
| 4-6 个 Part | 拆成 2 次提交 |
| 7+ 个 Part | 每 3 个 Part 提交一次 |

每次 commit 后必须 build 验证通过，才能继续下一个任务。

commit 格式：`feat: batch-N Part{X}[-{Y}] 一句话描述`

## 为什么有效

- 出问题可以精准 revert 到上一个 commit，不影响其他改动
- 审核者可以分步审核，不用一次看完所有改动
- build 错误能立即发现，不会积累到最后

## 适用条件

- 多任务（Part）组成的大 Batch
- 有构建步骤的项目
- 需要审核的工作流
