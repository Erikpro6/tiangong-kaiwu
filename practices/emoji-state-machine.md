# 实践: Emoji State Machine — 轻量级任务状态流转

> 提炼自 VoiceOS 3.0 progress.md 看板系统

## 问题

多角色异步协作时，缺乏统一的状态标记方式。执行者不知道哪些任务可以开始，审核者不知道哪些待审，指挥者无法一眼看清全局进度。传统看板工具（Jira / Trello）对 AI Agent 不可操作。

## 方案

用一个 Markdown 文件（如 `progress.md`）+ 固定列宽表格 + Emoji 状态标记，实现轻量级任务队列：

### 状态流转

```
🔴未开始 → 🟡进行中 → 🟢待审核 → ✅已完成 → 🔵已部署
                                         ↘ ❌打回 → 🟡进行中（重新执行）
```

### 表格格式

```markdown
| Batch | 状态 | 内容 | Spec | 审核报告 |
|-------|------|------|------|----------|
| B101 | ✅已完成 | 用户认证流程 | specs/batch-101 | reviews/batch-101 |
| B102 | 🟢待审核 | 仪表盘布局 | specs/batch-102 | — |
| B103 | 🟡进行中 | API 对接 | specs/batch-103 | — |
| B104 | 🔴未开始 | 部署上线 | specs/batch-104 | — |
```

### 规则

1. **状态唯一**: 每个 Batch 只有一个状态，不存在"半完成"
2. **流转单向**: 只能沿箭头方向推进（打回除外）
3. **谁改状态**: 执行者改 🟡/🟢，审核者改 ✅/❌，部署者改 🔵
4. **零遗漏**: 表格按序号排列，一眼看出跳号或遗漏

## 为什么有效

- **AI 可读可写**: Markdown 表格是纯文本，任何 Agent 都能解析和修改
- **Git 可追踪**: 每次状态变更都有 commit 记录，可回溯
- **零工具依赖**: 不需要 Jira/Trello/API，一个文件搞定
- **固定列宽**: `grep` 即可筛选特定状态的所有任务
- **视觉密度高**: 一屏可看 30+ 任务的状态，比卡片式看板信息密度高 10 倍

## 适用条件

- 2-6 个 AI Agent 角色异步协作
- 任务有明确的前后依赖关系
- 需要全局进度可视化
- 工作在 Git 仓库中（利用版本控制追踪状态变更）

## 实战证据

VoiceOS 3.0 项目用此方案追踪 **109 个 Batch**，零遗漏、零状态不一致。指挥者（北斗）每轮只需扫一眼 progress.md 就能判断下一步该做什么。相比 Phase ABCD 早期用散落的 commit message 追踪进度，状态可见性提升显著。
