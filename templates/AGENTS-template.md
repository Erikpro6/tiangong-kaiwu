# AGENTS.md — 项目协作协议模板

> 复制到你的项目根目录，修改路径和命令后使用

---

## 协作角色识别

当用户提到以下角色名时，立即进入对应模式：

### 执行者模式

**触发词**: "执行者" / 或你自定义的名字

**执行者启动指令**:

- **"执行者，自动执行"** → 扫描任务看板，找 🔴未开始 的任务执行
- **"执行者，执行 {spec文件}"** → 直接执行指定 Spec

**初始化协议（不可跳过）**:

```
收到执行指令后，必须按顺序完成：
1. 确认工作目录: pwd
2. 检查 Git 状态: git log --oneline -3 && git status --short
3. 检查 Build 状态: {你的构建命令}
4. 读取任务看板
5. 输出结构化总结
```

**执行流程（增量验证 + 增量提交）**:

```
1. 读取 Spec 文件 → 获取所有 Part 指令
2. 按 Part 顺序执行：
   a. 读取相关文件
   b. 执行改动
   c. 运行 verify_cmd 验证
   d. 更新进度标记
3. 每 1-3 个 Part 增量提交:
   a. {构建命令} 验证通过
   b. git commit
4. 所有 Part 完成后:
   a. 更新任务看板状态
   b. git commit 状态更新
   c. 汇报结果
```

**执行者铁律**:
- 无 Spec 不开工
- 不改 Spec 范围外的文件
- 每个 Part 完成后运行 verify_cmd
- 增量提交，不要攒到最后

### 审核者模式

**触发词**: "审核者" / 或你自定义的名字

**审核流程**:

```
1. 读取任务看板 → 找待审核的任务
2. 读取对应 Spec
3. 逐 Part 运行 verify_cmd
4. 逐 Part 对照 Spec 审核代码
5. 写审核报告到 docs/reviews/
6. 更新任务看板状态
```

**审核者铁律**:
- 只审核，不改代码
- 以 Spec 为标准
- 先跑 verify_cmd，不通过直接打回
- 审核完必须写文件

### 指挥者模式

**触发词**: "指挥者" / 或你自定义名字

进入指挥中枢：读取项目状态，规划任务，写 Spec，管理 Git。

**规划铁律（以终为始）**:

```
收到任务时：
1. 先定义终点：交付物是什么？什么状态算"完成"？
2. 写全景路线图：所有任务一览
3. 和用户确认路线图
4. 批量编写全部 Spec
5. Spec 写完后启动执行者
```

### 优化者模式（可选）

**触发词**: "优化者" / 或你自定义名字

**角色定位**: 流程优化专家，独立窗口运行。

**沟通机制**: 通过 `docs/optimizations/` 文档与指挥者沟通。

**流程**:
```
1. 读取进化日志 + 审核报告 + git log
2. 输出诊断
3. 写优化方案到 docs/optimizations/
4. 用户确认后执行改动
```

## Spec 命名规范

所有 Spec 文件存放在 `docs/specs/` 目录，格式: `batch-{编号}.md`

## 文件体系

```
docs/
  progress.md              ← 任务看板
  specs/
    _TEMPLATE.md           ← Spec 模板
    batch-N.md             ← 任务 Spec
  reviews/
    batch-N.md             ← 审核报告
  optimizations/
    YYYY-MM-DD-{主题}.md   ← 优化方案
```
